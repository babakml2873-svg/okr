# سامانه مدیریت OKR

پلتفرم مدیریت اهداف و نتایج کلیدی (Objectives & Key Results) با رابط کاربری کاملاً فارسی و راست‌به‌چپ، تقویم شمسی و محاسبه خودکار پیشرفت در چهار سطح شرکت، دپارتمان، تیم و فرد.

> An OKR management platform with a fully Persian, right-to-left interface, the Jalali calendar, and automatic progress roll-up across company, department, team and individual levels.

---

## پشته فناوری

- **Next.js 15** (App Router، React Server Components) + **React 19** + **TypeScript** (strict)
- **Tailwind CSS v4** با کامپوننت‌های سبک shadcn/ui روی **Radix UI**
- **PostgreSQL 16** + **Prisma** (با مهاجرت‌های نسخه‌بندی‌شده)
- **NextAuth v5** — احراز هویت با ایمیل و رمز عبور (bcrypt، نشست JWT)
- **Recharts** برای نمودارها، **ExcelJS** برای خروجی اکسل، **Zod** برای اعتبارسنجی
- **Vitest** برای تست واحد و **Playwright** برای تست end-to-end

## راه‌اندازی سریع

### پیش‌نیازها

- Node.js 22 یا بالاتر
- PostgreSQL 16 (یا Docker)

### ۱. نصب و پیکربندی

```bash
npm install
cp .env.example .env
```

سپس در فایل `.env` مقدار `AUTH_SECRET` را تولید کنید:

```bash
openssl rand -base64 32
```

### ۲. آماده‌سازی دیتابیس

```bash
npm run db:migrate   # اجرای مهاجرت‌ها
npm run db:seed      # ساخت داده‌های نمونه سازمان «نیوماو»
```

### ۳. اجرا

```bash
npm run dev          # حالت توسعه روی http://localhost:3000
# یا
npm run build && npm start
```

### اجرا با Docker

```bash
docker compose up --build
```

اپلیکیشن روی `http://localhost:3000` و PostgreSQL روی پورت `5432` بالا می‌آید. مهاجرت‌ها هنگام راه‌اندازی به‌صورت خودکار اعمال می‌شوند. برای پر کردن داده‌های نمونه:

```bash
docker compose exec app npx tsx prisma/seed.ts
```

## معماری

```
UI (Server Components + client islands)
        │
Server Actions ─┐
                ├─→  Services  ──→  Prisma  ──→  PostgreSQL
REST /api/v1 ───┘       │
                        ▼
              Domain (توابع خالص، بدون I/O)
```

- **لایه دامنه** (`src/lib/okr`, `src/lib/date`, `src/lib/auth`): موتور محاسبه پیشرفت، سیگنال سلامت، roll-up وزن‌دار، تبدیل تقویم شمسی و ماتریس دسترسی. هیچ وابستگی به دیتابیس ندارد و کاملاً تست‌پذیر است.
- **لایه سرویس** (`src/server/services`): تنها جایی که به دیتابیس دسترسی دارد. هر تابع یک `SessionContext` می‌گیرد، همیشه کوئری‌ها را با `organizationId` محدود می‌کند و پیش از هر تغییر `requirePermission` را صدا می‌زند.
- **دو مسیر ورودی**: Server Actions برای فرم‌های رابط کاربری و `/api/v1` برای یکپارچه‌سازی و تست — هر دو روی همان سرویس‌ها سوارند، پس منطق تکراری وجود ندارد.
- **پیشرفت کش‌شده**: ستون‌های `progress` و `health` در هر نوشتن، داخل یک تراکنش، دوباره محاسبه و تا بالای درخت هم‌راستایی منتشر می‌شوند.

### ساختار پوشه‌ها

```
prisma/            schema, migrations, seed
src/
  app/
    (auth)/        ورود و ثبت‌نام
    (app)/         داشبورد، اهداف، نتایج کلیدی، بازبینی، گزارش، تنظیمات
    (print)/       ویو چاپ گزارش‌ها (بدون پوسته اپ)
    api/           NextAuth، REST v1، خروجی اکسل
  components/      ui (پایه)، okr، charts، layout، shared
  server/          db، auth، context، services، actions
  lib/             okr، date، format، auth، validation
e2e/               تست‌های Playwright
```

## موتور محاسبه پیشرفت

پیاده‌سازی در `src/lib/okr/progress.ts`، خروجی همیشه بین ۰ تا ۱۰۰:

| نوع متریک | فرمول                                  | مثال                   |
| --------- | -------------------------------------- | ---------------------- |
| افزایشی   | `(current − start) / (target − start)` | دامداری فعال: ۲۰ ← ۱۰۰ |
| کاهشی     | `(start − current) / (start − target)` | نرخ خطا: ۱۰٪ ← ۲٪      |
| دوحالته   | `۰` یا `۱۰۰`                           | انتشار اپ موبایل       |
| مرحله‌ای  | مراحل انجام‌شده ÷ کل مراحل             | ۵ مرحله استقرار        |

**رنگ‌بندی** (`progressBand`): زیر ۳۰٪ قرمز، ۳۰ تا ۷۰٪ زرد، بالای ۷۰٪ سبز.

**سیگنال ریسک** (`calculateHealth`) مفهومی جداست: پیشرفت واقعی را با پیشرفت مورد انتظار در آن مقطع از کوارتر مقایسه می‌کند و امتیاز اطمینان مالک را هم لحاظ می‌کند — پس هدفی که عدد خوبی دارد ولی از برنامه عقب است، «در معرض ریسک» علامت می‌خورد.

**پیشرفت هدف** میانگین وزن‌دار نتایج کلیدی است. اگر `rollupMode` روی «نتایج کلیدی و اهداف زیرمجموعه» باشد، اهداف فرزند هم وارد میانگین می‌شوند (با پیمایش بازگشتی و محافظت در برابر حلقه).

## دسترسی‌ها

| نقش             | دسترسی                                                                       |
| --------------- | ---------------------------------------------------------------------------- |
| **مدیر سامانه** | همه‌چیز در سازمان + مدیریت اعضا، دپارتمان، تیم، کوارتر و تنظیمات             |

## استقرار

### Vercel

پروژه بدون تغییر روی Vercel اجرا می‌شود. یک دیتابیس PostgreSQL مدیریت‌شده (مثل Neon یا Supabase) بسازید و این متغیرها را تنظیم کنید:

| متغیر          | توضیح                           |
| -------------- | ------------------------------- |
| `DATABASE_URL` | رشته اتصال PostgreSQL           |
| `AUTH_SECRET`  | خروجی `openssl rand -base64 32` |

سپس در مرحله build دستور `npm run build` (که خودش `prisma generate` را اجرا می‌کند) و برای اعمال مهاجرت‌ها `npx prisma migrate deploy` را اجرا کنید.

### Self-host

از `docker compose up --build` استفاده کنید یا ایمیج را جداگانه بسازید. `Dockerfile` خروجی standalone می‌سازد و ایمیج نهایی با کاربر غیر-root اجرا می‌شود.

## خروجی PDF

گزارش‌ها از طریق **ویو چاپ مرورگر** به PDF تبدیل می‌شوند: در صفحه هر گزارش دکمه «چاپ / خروجی PDF» صفحه‌ای بدون سایدبار و توپ‌بار باز می‌کند که با CSS مخصوص چاپ (`@media print` در `globals.css`) برای کاغذ A4 بهینه شده است. این روش، برخلاف کتابخانه‌های تولید PDF، شکل‌دهی حروف فارسی و چیدمان راست‌به‌چپ را بدون هیچ تنظیم اضافه‌ای درست رندر می‌کند و روی محیط‌های serverless هم بدون وابستگی سنگین کار می‌کند.
